# 产品树与功能取舍准则

> 本文档是功能取舍的最高准则，2026-09-18 起生效。任何新工作包（无论由谁/哪个 AI 实施）必须先通过本文档的准入三问。
> 由来：前作 SnapSync 的教训——后台复杂度（三条摄入链路、OCR、JSON 化、分块并行建树）全是"暗管"，评委可见面只有 2 个功能；技术投入没有转化为产品感知。

## 定位（2026-09-18 升级）

**Preflight 是 AI 时代可信声明的证据基础设施（Trust Layer）：验证"陈述在材料中是否有可定位的依据"，不验证"陈述是否符合外部现实"。** 任何「材料 × 标准」的组合都可以预审——比赛评审标准只是当前默认的一份 Rubric 文件，不是产品边界。诚实边界是卖点：数字矛盾、缺失依据、过度宣称是可验证的内部一致性风险；"AI 判真假"永远不做。

**架构定位 ≠ 当前能力**：通用「材料×标准」模型是架构目标；当前实现仅支持 UTF-8 Markdown（≤1 MiB）——比赛期内先把 Markdown + AIC 模板做完整，格式扩展（PDF/PPTX/DOCX）不得因定位升级自动进入任何迭代。对外产品表述用价值句（如"让重要材料中的每个关键结论，都能追溯到真实依据"），"Trust Layer / 证据基础设施"仅作内部 North Star，不上首页。

## 一、产品树五问（每次规划先回答）

1. **3 分钟 demo 主流程是什么？** 上传材料+绑定标准 → AI 预检（含幻觉引用被当场拒绝）→ 评分矩阵（每个结论点回原文）→ 答辩模拟追问 → 修复后重跑 Diff。
2. **首页应该展示什么？** 报告中心：最近检查一览（每份材料的已确认关联数/缺失/风险计数）+ 开始预检入口。不是文件管理器。
3. **评委必须看到哪 5 个功能？** AI 预检、评分矩阵报告、证据点回原文、答辩模拟、修复重跑对比。
4. **哪些技术永居幕后？** Block/Span/Locator 解析、quote 验证门（除"拒绝幻觉"瞬间外）、溯源与版本锚定机制、SQLite 事务。它们只通过叶子显形。
5. **叶子怎么长？** 默认 Controlled Breadth / 树冠优先（2026-09-18 起）：每个 iteration 交付一片用户可独立感知的叶子（屏幕可指认、demo 可单独展示）；预算为小时级 vertical slice，「1–2 天一个迭代」作废。不主动新建树干；仅当某片叶子确需时单独立树干计划并审批。iteration 数量不设上限，10/7 Feature Freeze 不变。候选顺序按真实依赖：I6 报告中心 → I7 Claim Inspector → I8 数字与跨材料矛盾 + Overclaim/Unsupported → I9 答辩 Grill → I10 修复工作台 → I11 重跑与版本 Diff → I12 第二垂直模板（简历×JD，纯 Rubric 文件，可插队）→ I13 导出提交包 → I14 审阅 UX。I13/I14 到点必须重新过准入三问，不得因「打磨/导出」绕过凑数禁令。

## 二点五、垂直场景（同一引擎，换一份 Rubric 文件）

| 场景 | 材料 | 标准 | 共同问题 |
| --- | --- | --- | --- |
| 参赛材料预审（默认模板） | 技术方案/PPT/README | 比赛评审标准 | 关键要求有没有可回溯的支撑？ |
| 简历与求职材料 | 简历/自述 | JD/岗位要求 | 每条经历与技能 claim 有出处吗？ |
| 技术方案评审 | 设计文档 | 评审 checklist | 取舍与风险写清楚了吗？ |
| 论文自查 | 草稿 | 投稿要求/审稿要点 | 声明与数据一致吗？ |
| 合规文档 | 政策/合同 | 条款清单 | 义务条款有无对应依据？ |
| 产品白皮书 | 宣传材料 | 事实核查清单 | 数字与对比有无来源？ |

以上只是换 `data/rubrics/*.json` 文件，零代码差异——这是"平台叙事"的工程根据，也是答辩"落地场景与推广"章节的现成素材。

## 三、树干→叶子映射表（"暗管"禁令）

| 树干（技术） | 必须养活的叶子（可见出口） |
| --- | --- |
| Block/Span/Locator | 行号列、点击定位原文行（Drawer/锚点高亮） |
| resolve_span 验证门 | 幻觉候选 `无效：quote_not_found` 徽章（demo 记忆瞬间） |
| proposed_by 溯源 | human/agent 徽章；AI 提议与人类裁决视觉可分 |
| (rubric_id, revision) 锚定 | 矩阵按标准版本渲染；标准更新历史不丢 |
| 事务原子性 | 负空间保证：接受操作永不出半成品状态 |
| LLM 适配层（env/超时/严格解析） | 明确的失败文案（未配置/超时/坏响应），绝不假装成功 |

规则：**新增任何树干结构前，先指认它养活哪片已有或即将有的叶子。** 指不出来 = 不做。

## 五、准入三问（最高规则）与并行施工治理

**准入三问**——每个新工作包必须回答，答不上即拒绝：
1. 它在哪个屏幕有入口？
2. 它的验收标准是什么（可运行的检查）？
3. 它在 3–5 分钟 demo 里占几秒？

**树干串行 / 树冠并行**（多 AI 算力涌入时的施工模型）：
- **树干串行**：contracts.py、storage、API 核心路径，任意时刻只有一个 implementer；不改既有表与端点语义。
- **树冠并行**：叶子页面、检查脚本、文档、benchmark 用例可拆成有界工作包并行施工，每包自带准入三问答案与独立验收。
- **显式拒绝清单**：好友/社交、通用设置中心、登录头像、无 demo 秒数的功能、打分模拟（✅❌ 或"AI 给 XX 分"）。
- 算力多 = 叶子长得快；不是树干变粗，更不是种新树。

## 五点五、Controlled Breadth / 树冠优先（2026-09-18）

- 每个 iteration 一个可独立感知的能力；小时级 slice。
- 不主动新建树干；叶子确需才立树干计划走审批。
- 反两个极端：不做社交/设置/凑数功能；也不做「只测不长」。
- 每片叶子验收后更新第四节账本。

## 六、事实性状态词表（措辞纪律，能力分级）

矩阵与报告只能说事实，不说裁决。词表按"对应检查是否真的执行过"分级——**没有相应的检查能力，就没有资格用相应的词**：

- **始终允许**（只陈述已实现能力的输出）：已确认关联 N 条 / 已关联 N 条 / 已绑定 rev N / 未评估 / **当前范围尚未发现引用**（必须能说明"当前范围"是什么，如"当前材料 109 个 Block"）。
- **门控词**（对应检查真正实现并执行后才允许出现；每条 Finding 必须能回答三问：搜索范围是什么？为什么得出此结论？点哪里能看到原始依据？）：
  - **缺失 / Missing**——Iteration 6 起可用（missing_evidence 必带检索范围，冻结契约早有此要求，CONTRACTS.md）；
  - **有矛盾 / Conflict**——跨文档/数字矛盾检测真正实现后（Iteration 7），不得凭 LLM 感觉；
  - **Overclaim / Unsupported Claim**——相应裁决规则实现后。
- **禁止**：已满足 / 已支撑 / 覆盖率 X%（裁决规则落地前）/ ✅❌ 满足芯片 / 分数预测。

## 七、5 秒测试（分阶段验收）

Iteration 6 完成后，打开首页，一个没见过产品的人 5 秒内能说出：
**「这是一个按评审标准预审材料、把每条要求点回原文的工具。」**
说不出来 = 打回重做首页。I6 首页不得承诺答辩模拟。

Grill 迭代完成后（预计 I9），同一测试的完整口吻为：
**「这是一个 AI 帮你按照评审标准预审材料、找风险、准备答辩的工具。」**

## 七点五、未来方向（赛后，比赛期内不实现、不写进 demo 承诺）

- **Layer 2 — Artifact Grounding（产物锚定）**：把"准确率 95%"这类声明锚定到代码/数据/实验产物（benchmark 目录、result.csv、commit hash），回答"有没有真实产物支撑"。扩展点：新增 Artifact 实体与 Claim↔Artifact 关联——现模型（Claim/Span/基于文件的 Rubric）已可容纳，无需重构。
- **Layer 3 — 持续验证**：材料或产物更新后重跑预检，形成 resolved/new/unchanged 的持续风险流（VersionDiff 契约已冻结）。
- **护栏**：永远不做"AI 判断外部真实性"；只做"可验证链路，让人和工具检查声明依据"。这两个方向的实现顺序与排期在赛后另行规划，当前任何迭代不得擅自拉入范围。

## 八、维护规则

- 每个迭代收口时更新第四节账本（状态与 demo 秒数）。
- 产品树结构变更（加枝/砍枝）需用户明确确认，任何 AI 不得自行加枝。
- MASTER_PLAN 保持 2026-09-15 冻结、不改正文。产品取舍与验收口径以用户后续明确指令和本文为准（MASTER_PLAN 自己规定「用户后续明确指令 > 本计划」）。
