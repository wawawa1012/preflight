# 原始要求片段模板（每次重写 3-5 条，每条一句话）

> 用法：按 Criteria Builder 场景，每次手写一段新的 raw 要求（换场景：比赛要点 / JD / 审稿要点三选一轮换）。粘贴进产品前不预排格式，保留"原始感"（允许口语、允许一条稍长），用于检验"原始要求 → 草稿 → 人工确认"是否自然。

```
{场景：如 校赛评审要点（v1_powder）}
1. {方案须说明数据来源和测试条件。}
2. {关键数字须能在材料中找到出处。}
3. {没做的事要诚实写出局限，不许夸大。}
4. {与已有方案对比须写清条件。}
5. {结论须有依据句支撑，结论与依据能点回去。}
```

## 自检

- [ ] 3-5 条，每条一句话，不過度打磨（留 1 条口语化的）。
- [ ] 我知道每条的本意（tester 笔记），用于判断草稿是否改意。
- [ ] 与上一轮场景不同，不抄 golden-v2 的 criterion 原文。
