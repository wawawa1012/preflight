# Scenario S2-6: model_failure_degradation（Coach/Grill 失败时优雅降级）

> Sprint 2 待执行资产（不改产品）。检验：Coach/Grill 失败时，已有来源、确定性结果、备答准备仍可用；系统说人话，不假装成功，不吞掉已有东西。

## USER GOAL

如果答辩教练/追问出不来（失败了），我已有的东西（来源、已出的检查结果、备答准备）不能丢，我要知道"失败了、为什么、现在还能干什么"。

## STARTING STATE（用户可见）

- 已有一场 Review：检查结果已有（≥3 条可见）、来源可点、准备清单/追问至少见过一次（或正在跑）。
- tester 不制造失败（不拔网、不改配置、不读 logs）；只观察自然失败或按 UI 诚实路径触发的失败（例如 UI 自己显示"失败/超时/未配置"，点重试一次）。**不许**用断网/改 key/调参/看后端日志"造"失败——那不是黑盒用户行为。
- 记得失败前"已有什么"（3 条结果标题 + 1 个可点的来源），用于失败后对照"丢没丢"。

## TASK（黑盒步骤）

1. 发起（或等待）一次 Coach/Grill，把从发起到结束的 UI 原话抄下来（含等待话术、失败话术、重试入口）。
2. 失败出现后（若一直成功，本 scenario 记"未触发"，不得硬造；见下），检查三样东西还在不在：
   a. 已有来源还点得回去吗？
   b. 确定性结果（已出的检查结论）还在吗？数字/标题变了吗？
   c. 备答准备（已有追问/清单/我的回答草稿）还在吗？
3. 按 UI 给的下一步走（重试一次，或"先用已有结果准备"），记录走通了吗。
4. 回答：这次失败是"优雅的"（说了失败+给了活路）还是"灾难的"（假装成功/吞东西/白屏）？

## ALLOWED KNOWLEDGE

- 允许：失败前后的 UI 原话、已有结果标题、来源可点性。
- 禁止：超时实现、模型名、provider、key 配置、backend logs、API、DB、代码路径。tester 不解释"为什么失败"，只记录"失败长什么样"。

## SUCCESS CONDITION（优雅降级三件套 + 一诚实）

- [ ] 失败说人话：明确说失败了（"没出出来/失败/超时"，不说"成功/已完成"），不转圈到天荒地老（>90 秒无话术 = 不优雅）。
- [ ] 已有来源仍可点回原文（抽 1 条验证）。
- [ ] 确定性结果仍在且不变（标题/数字与失败前一致，或明确标注"这是失败前的结果"）。
- [ ] 备答准备仍可用（已有追问/清单/草稿不丢失），且有下一步（"重试"或"先用已有结果"二选一，一点就走通）。

## BLOCKED CONDITION

- 失败后白屏/结果区被清空且无恢复；来源点不回去；重试点了没反应。
- 失败无话术（一直转圈/空白页）> 90 秒。
- 需读 logs/API/改配置恢复 → BLOCKED，本轮作废。

## TRUST FAILURE

- 假装成功：失败了却显示"已完成/教练已就绪"，点进去是空的或复读旧话术。
- 吞东西：失败后已有结果/来源/草稿丢失且无说明（丢失比失败严重得多，致命候选）。
- 编答案充数：失败后用一句与材料无关的"标准答案"冒充反馈（见 traps T7；出现即致命）。
- 禁用词总结失败："失败但你的材料已满足要求/覆盖率 100%"（失败+背书双重撒谎，致命）。
- 失败归因撒谎："你的材料有问题导致失败"，但换一份干净材料同样失败（把系统失败推给用户；记录复现过程后判 TRUST）。

## METRICS

- `BLOCKED_FLOWS`（主）：失败后东西丢了/重试走不通/白屏次数。
- `TRUST_FAILURES`：假装成功/吞东西/编答案/禁用词计数（一票否决级）。
- `WAIT_WITHOUT_VALUE`：无话术等待秒数（>90 秒即候选 BLOCKED）。
- `USEFUL_MOMENTS`（降级后仍可用的：来源/结果/准备各算 1 个）/ `TIME_TO_FIRST_VALUE`（失败后到"知道还能干什么"的时长）/ `DEAD_ENDS`（失败后不知道干什么）/ `INTERNAL_CONCEPT_LEAKS`（堆栈/模型名/key 裸奔）/ `DELIGHT_MOMENTS`（失败话术诚实+活路清晰则记："虽败犹荣"）。

## 未触发失败怎么办

- 若连续 2 次自然成功：本轮记 `degradation_not_triggered`， verdict 写 `dry-run`，不硬造失败，不判 PASS。
- 失败场景的正式覆盖靠 Sprint 2 执行轮的自然失败 + traps T4（criterion timeout）的诚实话术审查；本 scenario 不授权任何造失败手段。

## 推荐 persona

- 主力：`enterprise_reviewer`（"失败了我的归档还在吗"）、`contestant`（"答辩前夜失败了还能备吗"）。
- 对抗：`adversarial_skeptic`（失败后逐条点来源，看吞没吞）。
