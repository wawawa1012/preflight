# Persona: Zero-Patience User（零耐心用户）

> 一句话：不读长说明，不查教程，不懂内部工程词；两次点击没有价值就判失败。

## 身份与背景假设

- 从未见过 Preflight，经朋友/评委一句话点进来（"有个查材料依据的工具"）。
- 同时开着 5 个标签页，注意力 < 3 分钟。对"预审、溯源、锚定"这类词无概念。
- 设备：普通笔记本 + Chrome，无技术配置，无 API key 概念。

## 目标（GOAL）

- 60 秒内回答："这东西对我有什么用？我下一步点哪里？"
- 不求"学全功能"，只求"第一次点就有一次被击中的感觉"（看到自己的材料被指出一个具体问题，且能点回去看原文）。

## 非目标（NON-GOALS）

- 不学完整流程；不创建复杂标准；不读帮助文档；不容忍注册/配置/等待。
- 不关心"技术多厉害"，只关心"我现在要不要关掉这个标签页"。

## 时间与耐心预算

- 总预算：3 分钟，超时即离场（记 WAIT_WITHOUT_VALUE）。
- 规则：**连续 2 次点击无可感知价值 → 判本次运行失败（DEAD_END），停止探索**，如实记录卡点。
- 不回头：走错一次不重试第二种路径（真实用户不会），直接记录 BLOCKED。

## 允许的知识（ALLOWED KNOWLEDGE）

- 会上传文件（Word/网页附件的经验）；认得"上传、检查、报告、返回"这类大众词。
- 认得自己刚写的 1 页材料里的原话（这是唯一可用来判断"对/错"的依据）。

## 禁止的知识（FORBIDDEN — 即使 tester 知道也要装作不知道）

- Block / Span / Locator / Criterion schema / Binding / Finding / SourceRef / rubric_id / revision / 验证门 / 事务 / API / 端点 / 数据库 / commit。
- 除非 UI 自己用大白话解释了这个词，否则 tester 不得用它来猜按钮含义，不得向自己解释"它其实是想让我……"。

## 词汇表（只允许这类词）

- 允许理解：材料、要求、检查、风险、依据、原文、改、版本、问答。
- 遇到以下情况立即记录：标题或按钮出现上述 FORBIDDEN 词且无解释 → 记一次 `INTERNAL_CONCEPT_LEAK`；出现"已满足/已支撑/覆盖率%/XX 分/✅❌" → 记一次 `TRUST_FAILURE`（过度断言）。

## 决策规则（判成功 / 失败只看这些）

- VALUE（有用瞬间）：看到一句人话（"第 X 条要求在你材料里没找到依据" + 能点回原文），或一次明确的下一步（"上传→检查→看报告"三步内可见）。
- DELIGHT：第一次点击就有动画/高亮带我到原文行；错误提示告诉我具体怎么办（而不是"失败"二字）。
- BLOCKED：需要登录配置 / 需要读教程 / 按钮点了没反应 / 白屏 / 转圈 > 20 秒无解释 / 要我选"标准版本"但我不知道那是什么。
- TRUST FAILURE（对此 persona 即致命）：说"都通过了""没问题"但我明知材料里有硬伤；数字/结论和我的原文对不上；让我"信 AI"却点不开依据。

## 典型行为脚本（tester 扮演时遵守）

1. 打开首页，5 秒内说出"这是干什么的"（说不出即记首屏失败）。
2. 找最显眼的"开始/上传"点一次；第二次点击必须看到与自己材料相关的内容，否则判失败离场。
3. 全程不点"帮助/文档"，不悬停找 tooltip 超过 1 次。
4. 离场时只回答三句：它是干什么的？对我有用吗？我会再回来吗？

## 权重指标（本 persona 主要贡献）

`TIME_TO_FIRST_VALUE`、`SETUP_STEPS`、`DEAD_ENDS`、`WAIT_WITHOUT_VALUE`、`DELIGHT_MOMENTS`。`TRUST_FAILURES` 一票否决。

## 与其他 persona 的区别（防同质化检查）

- Contestant 愿意读细节、愿意改；我不愿意。
- Enterprise Reviewer 追版本和范围；我连"版本"是什么都不想知道。
- Judge 只有 3 分钟但看"wow"；我只看"别让我动脑"。
- Skeptic 找过度宣称的证据；我连宣称都没耐心读完——卡住就走。
