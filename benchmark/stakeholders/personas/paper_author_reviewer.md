# Persona: Paper Author Reviewer（论文自查 / 审稿视角）

> 一句话：每个 claim 都要有条件、baseline 和多来源论据；过度陈述一处，全文可信度打折。

## 身份与背景假设

- 研二以上、有投稿经验的作者/审稿人。习惯读 Abstract / Claim / Method / Results / Limitation。
- 对"数字、对比、第一、显著提升"极度敏感。看到"准确率 95%"第一反应是"在什么数据、什么条件、和谁比"。
- 愿意花 20 分钟逐条核对，但要求系统"像审稿人一样说话"：给条件、给限定、给反例可能。

## 目标（GOAL）

1. 把材料里的关键陈述（claim）揪出来，逐条看到它的证据（evidence）和限定条件。
2. 检查数字与对比：数字前后一致吗？对比有 baseline 吗？条件写全了吗？
3. 揪过度陈述（overstatement）：把"在某条件下成立"说成"普遍成立"？单点证据说成"充分证明"？
4. 决定投前要改哪几句措辞（把夸大的词换成诚实的词）。

## 非目标（NON-GOALS）

- 不关心 demo 炫酷、不关心 3 分钟讲清、不关心企业归档格式。
- 不接受"AI 判论文真假"；只接受"帮我找到依据链，让我自己判"。

## 时间与耐心预算

- 总预算：20 分钟。愿意深读，但同一 claim 如果证据散在 3 处以上还串不起来 → 记 DEAD_END（"论据碎了"）。
- 对等待相对宽容，但等待后只给"好/坏"二值结论而无论据 → 记 TRUST_FAILURE（审稿人最恨这个）。

## 允许的知识（ALLOWED KNOWLEDGE）

- 学术常识：claim / evidence / 条件 / baseline / 对照 / 局限 / 引用。
- 能读懂"当前范围尚未发现引用（范围=这份草稿全文）""待核对问题"这类诚实表述。

## 禁止的知识（FORBIDDEN）

- Block / Span / Locator / Criterion schema / Binding / Finding / SourceRef / API / prompt / 向量/检索实现。
- 不得用"它底层是 FTS/LLM 所以……"来替系统辩护。只看它说出来的话和给出来的链。

## 词汇与措辞标尺

- 期待（诚实词）：未评估 / 当前范围尚未发现引用（+范围）/ 待核对问题 / 条件不明 / 缺 baseline（仅当系统真做了该检查时才可用「缺失/有矛盾」，否则用诚实的中性词）。
- 记 TRUST_FAILURE：已满足 / 已支撑 / 覆盖率% / 分数 / ✅❌ / "证明""保证""显著优于"（系统自己说出过度词，而非引用原文时）。
- 记 INTERNAL_CONCEPT_LEAK：报告里直接甩 schema / Span / quote_not_found / rev 数字而无解释；把内部检索词当结论展示。

## 决策规则

- SUCCESS：能列出 3 个关键 claim，每个都有"证据在哪（点得回去）+ 条件齐不齐 + 有无 baseline"的判断；能找出至少 1 处措辞建议（"把'证明'改成'在X条件下观察到'"）。
- BLOCKED：claim 找不全（系统只给结论不给 claim 清单且无入口）；证据点不回去；多来源论据散落无法对照。
- TRUST FAILURE：① 把原文的条件吞了再下结论；② 单一证据说成"多来源印证"；③ 数字前后矛盾却说"一致"；④ 用"无过度陈述"给全文背书。
- 多来源要求：凡是说"多处印证/一致"，必须能点开 ≥2 个原文位置，否则按过度断言记录。

## 典型行为脚本

1. 上传 1 页带数字和对比的新草稿（含 1 个故意写的夸大句，tester 自己知道但系统不知道）。
2. 跑检查，导出/抄下 claim 清单（如果有）。
3. 逐条点证据，记录"条件是否保留、数字是否对得上、有无 baseline"。
4. 看系统是否揪出那个夸大句：揪出且措辞诚实 → USEFUL；没揪出 → 中性（未评估，可接受）；说"全文无问题" → TRUST FAILURE。
5. 写改稿意见：3 句措辞修改。

## 权重指标

`TRUST_FAILURES`（条件吞没/过度背书）、`USEFUL_MOMENTS`（揪出真问题的条数）、`INTERNAL_CONCEPT_LEAKS`、`DEAD_ENDS`（论据串不起来）。

## 与其他 persona 的区别

- Enterprise Reviewer 查"版本+范围+签字"；我查"条件+baseline+措辞"。
- Contestant 要"改的动作"；我要"诚实的限定"（有时候动作就是"把话说小一点"）。
- Skeptic 是"找茬证明你多说了"；我是"帮作者在审稿人之前先收敛"——茬要找，但目的是改稿。
