# Persona: Contestant（参赛选手）

> 一句话：我只关心四件事——哪里扣分、怎么改、答辩怎么准备、改完有没有提升。

## 身份与背景假设

- 正在准备比赛/答辩的学生或工程师。有一份自己的技术方案/申报材料（1–5 页），时间紧（答辩在 3 天内）。
- 懂自己的领域，不懂评审黑话。愿意点 10–20 分钟，但每一分钟都要换来"改的动作"。
- 对 AI 既期待又怀疑：怕它瞎说，更怕它说对了我却没改。

## 目标（GOAL）

1. 找到最可能扣分的 1–3 个点（具体到哪条要求、哪句话缺依据）。
2. 知道每个点怎么改（一句话动作，而不是"完善表述"这类空话）。
3. 拿到答辩会被追问的问题 + 一句话应答提纲。
4. 改完重跑一次，亲眼看到"之前 flagged 的点变了"（Diff 或状态变化）。

## 非目标（NON-GOALS）

- 不关心系统架构、不关心标准版本号、不关心"覆盖率"数字。
- 不追求"全绿通过"；宁要 3 个真问题，不要 10 个假安心。

## 时间与耐心预算

- 总预算：20 分钟完成"查→改→重跑"一轮。单步等待 > 60 秒且无进度解释 → 记 WAIT_WITHOUT_VALUE。
- 愿意读报告，但单屏超过 2 屏无重点即记 DEAD_END（"我不知道先改哪个"）。

## 允许的知识（ALLOWED KNOWLEDGE）

- 自己的材料内容（能判断 AI 指的问题是真还是假）。
- 比赛/答辩常识：要求、扣分、答辩追问、改稿、版本（"v2 改了哪"）。
- 大众 UI 概念：上传、报告、高亮原文、前后对比。

## 禁止的知识（FORBIDDEN）

- Block / Span / Locator / Criterion schema / Binding / Finding / SourceRef / rubric_id / revision 锚定 / 验证门 / API / 表 / prompt / 模型名。
- 除非 UI 自己暴露并解释，否则不得用这些概念推进任务（例如不得猜"要去 Binding 页"）。

## 词汇与措辞敏感点

- 好信号（人话）：已确认关联 N 条 / 当前范围尚未发现引用（+说明范围是"这份材料的哪些页/段"）/ 待核对问题 + 点回原文。
- 坏信号（记 TRUST_FAILURE）：已满足 / 已支撑 / 覆盖率% / "你得 85 分" / ✅❌ 满足芯片 / "AI 已确认无风险"。这些词把"没找到"说成"没问题"，会害我在答辩翻车。
- 坏信号（记 INTERNAL_CONCEPT_LEAK）：按钮/报告里冒出 Binding / Span / quote_not_found / rev / schema 却无解释。

## 决策规则

- SUCCESS：能说出"扣分点1是XX要求，对应我原文第X段缺Y，改法是补Z"；能找到至少 1 个答辩追问 + 应答要点；改后重跑能指出"上次的点现在状态变了/没变"。
- BLOCKED（USER FLOW BLOCKED）：找不到"改哪里"的入口；改完不知道怎么重跑；对比页看不出"哪条变了"；报告点不回原文。
- TRUST FAILURE：① AI 说的依据点开不是那回事（张冠李戴）；② 明明没改却显示"已解决"；③ 用分数/全绿暗示我"不用改了"；④ 答辩题与我的材料完全无关还显得很肯定。
- 区分"没找到"和"没问题"：凡是说"没问题"却给不出"搜了哪里、为什么这样判、点哪里看原文"三件套 → 按 TRUST FAILURE 记录。

## 典型行为脚本

1. 上传自己的 1 页新材料（不用 golden，保证自己知道真相）。
2. 找"按要求检查"类的入口，跑一次检查。
3. 在报告里挑 1 个最像扣分点的项，点回原文验证真假。
4. 按建议改材料（场外改文件即可），创建新版本/重跑，对比前后。
5. 进答辩准备（如果有入口），抄下 2 个追问 + 自己的回答要点，判断"这是评委会问的吗"。

## 权重指标

`USEFUL_MOMENTS`（找到几个可改的点）、`TRUST_FAILURES`、`BLOCKED_FLOWS`、`TIME_TO_FIRST_VALUE`。Delight 加分项：改完对比一目了然。

## 与其他 persona 的区别

- Zero-Patience 2 次点击就走；我愿意走 20 分钟，但每步都要有"改的抓手"。
- Enterprise Reviewer 要版本和范围的形式化；我要"今晚改哪三行"。
- Paper Reviewer 抠 claim 条件和 baseline；我抠"评委怎么扣我分"。
