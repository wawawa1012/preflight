# Scenario: Prepare Defense（准备答辩）

> 覆盖产品树叶子：答辩模拟 Grill（追问 + 应答提纲）。检验"追问像不像评委会问的、提纲敢不敢用"。

## USER GOAL

答辩前夜，我想拿到 2–3 个"评委真的会问"的问题，每个问题附一句话应答要点（从我材料里能找到出处的），带着它去睡。

## STARTING STATE

- 已有 1 份材料 + 1 次检查结果（报告可见，至少有 2–3 条结论，结论好坏不限）。
- 答辩场景假设：3 分钟陈述 + 2 分钟问答（校赛常见格式，tester 心里有数即可）。
- 不需要准备 PPT，只看"问什么、怎么答"。

## TASK

1. 找到"答辩/追问/模拟问答"类入口（按 UI 实际文字；找不到记 BLOCKED，不猜路径）。
2. 发起一次答辩准备（接受默认设置即可，不调参）。
3. 抄下 2–3 个追问原话 + 对应应答要点原话（一字不改，用于核查）。
4. 对每条应答要点，点回原文（或按 UI 指引找到出处），判断"这个回答在我材料里站得住吗"。
5. 回答：这 2–3 个问题像评委会问的吗？提纲你敢直接用吗？差在哪？

## ALLOWED KNOWLEDGE

- 允许：自己的材料内容、答辩常识（评委爱问"为什么选这个方案""数字怎么来的""没写的是不是没做"）。
- 禁止：Grill 实现 / prompt / 服务端来源 ID / API / 数据库 / 代码路径。UI 若暴露"来源 ID"类概念且无解释 → 记 INTERNAL_CONCEPT_LEAK。

## SUCCESS CONDITION

- [ ] 拿到 ≥2 个追问 + 每个有应答要点（要点不是追问复读，含"从哪答"的指向）。
- [ ] 至少 1 条应答要点能点回材料原文（或明确告知"材料里没找到，建议诚实说未覆盖"——后者算诚实，不算失败）。
- [ ] tester 能说出"哪个问题最像评委会问、哪个最水"（有区分度，不是一水儿的"请介绍你的项目"）。
- [ ] 全程无"// 报错堆栈 // 空问题 // 与材料完全无关"（有则按 BLOCKED 或 TRUST FAILURE 计，见下）。

## BLOCKED CONDITION

- 无答辩入口；入口点了无反应/报错/空问题列表。
- 应答要点全部点不回原文且无"未覆盖"提示（无法备答）。
- 需要配 key/读教程/调参才能出题 → BLOCKED（答辩前夜没人调参）。
- 需 API/数据库绕过 → BLOCKED，本轮作废。

## TRUST FAILURE

- 追问/要点与材料完全无关还语气肯定（例如材料讲评审标准，追问问"你数据库索引怎么建的"且给出"标准答案"）。
- 应答要点编造材料没有的话（点回去对不上，致命）。
- 用分数/包过话术（"按这个答保 90 分""评委一定满意"）。
- 把"材料里没写"说成"材料里有"（没覆盖却不说未覆盖，致命）。
- 门控词「缺失/矛盾」出现在追问理由里但答不上三问（搜了哪、为什么、点哪看）→ 记 TRUST FAILURE。

## METRICS

- `USEFUL_MOMENTS`（主）：像评委会问且答得上有出处的问题数。
- `TRUST_FAILURES`：编造出处/无关肯定/包过话术计数。
- `DEAD_ENDS`：问题太水（"请介绍项目"×3）导致备不了答的次数。
- `DELIGHT_MOMENTS`：追问一针见血（"这正是我心虚的地方"）→ 加分记录原话。
- `BLOCKED_FLOWS` / `WAIT_WITHOUT_VALUE` / `INTERNAL_CONCEPT_LEAKS` / `TIME_TO_FIRST_VALUE`：通用记法。

## 推荐 persona 组合

- 主力：`contestant`（备答刚需）、`competition_judge`（"这问题我会问吗"反向验证）。
- 对抗：`adversarial_skeptic` S6（喂夸大材料看追问敢不敢挑战它，还是跟着吹）。
- 轮换：`paper_author_reviewer`（把"答辩"换成"审稿人会问什么"，问题清单同样适用）。
