# Scenario: First Review（第一次检查）

> 覆盖产品树叶子：材料上传 → AI 预检 → 评分矩阵报告 → 点回原文。对应 5 秒测试与 3 分钟 demo 主线。

## USER GOAL

作为一个第一次打开产品的人，我想把我的一份材料按一份评审要求查一遍，看到"哪条要求有依据、哪条还没找到"，并且每条都能点回去看原文。

## STARTING STATE（用户可见状态，不含内部实现）

- 已打开产品首页（浏览器，无需登录配置；如需登录则该步骤计入 SETUP_STEPS）。
- 手头有一份自己刚手写的 1 页 Markdown 材料（≤50 行，含 2–3 个关键陈述 + 1 个数字，tester 自己知道真相，但 scenario 不给答案）。
- 有一份评审要求清单（产品自带的默认模板即可，不用自己写）。

## TASK（黑盒任务步骤，只写人能点的动作）

1. 从首页找到"开始/上传/新建检查"类入口，把材料放进去。
2. 选择（或确认）要用哪份评审要求来查（如果产品自动选了，记下它是否告诉了你"按哪个版本查的"）。
3. 发起一次检查，等待结果（掐表）。
4. 打开检查报告：浏览每条要求的结论，随机抽 3 条点回原文。
5. 说出：这次查了多大范围、按哪个版本查的、AI 提的和人确认的是否分得清。

## ALLOWED KNOWLEDGE

- 只允许用 UI 上的词和自己的材料内容做判断。
- 允许知道：材料、要求、检查、报告、依据、原文、版本（rev N 的大众含义）。
- 禁止使用：Block / Criterion schema / Binding / Finding / SourceRef / API / 数据库 / 代码路径 / oracle 答案。不得猜"后台怎么存的"。

## SUCCESS CONDITION（全部满足才算成功）

- [ ] 从首页到看到第一条与自己材料相关的结论，SETUP_STEPS ≤ 3（Zero-Patience/Judge 视角）。
- [ ] 报告中每条抽查结论（3 条）都能点回原文对应位置（行/段高亮或同等可见方式）。
- [ ] 报告能说清范围（"查了这份材料全文"或等价表述）和标准版本（rev N 或等价表述），或诚实标注"未评估"。
- [ ] 人确认的与 AI 提议的有视觉或文字区分（或明确告知"暂无人确认"）。

## BLOCKED CONDITION（出现任一即记 USER FLOW BLOCKED，不得绕过）

- 找不到上传/开始入口；上传后无反馈；检查按钮点了没反应。
- 等待 > 90 秒无进度话术；白屏/报错且无下一步指引。
- 报告打不开；结论点不回原文；需要读教程/配 key 才能继续。
- 处理：停止，按 `report-template.md` 记录 BLOCKED，不许用 API/数据库/读源码绕过后算成功。

## TRUST FAILURE（出现任一即记，致命项否决本轮）

- 报告出现禁用词：已满足 / 已支撑 / 覆盖率% / 分数预测 / ✅❌ 满足芯片（过度断言）。
- 点回原文对不上（张冠李戴/截断改意/原文没有这句话）却语气肯定。
- 空/极短材料也给出"通过/无风险"类总结。
- AI 提议显示为"已确认/已关联"（人机混淆）。
- 门控词「缺失/有矛盾」出现但答不上三问：搜了多大范围？为什么这样判？点哪里看原文？

## METRICS（本 scenario 必记）

- `TIME_TO_FIRST_VALUE`（主）：从首页到第一条可点回原文的结论，秒表。
- `SETUP_STEPS`：到发起检查共几步。
- `BLOCKED_FLOWS` / `DEAD_ENDS`：卡住几次、走进死胡同几次。
- `TRUST_FAILURES` / `INTERNAL_CONCEPT_LEAKS`：按 metrics.md 计数。
- `WAIT_WITHOUT_VALUE`：无意义等待秒数。
- `USEFUL_MOMENTS`：抽查 3 条中有几条真有用（点得回去且说得对）。
- `DELIGHT_MOMENTS`：第一次点回原文的高亮/动画等加分瞬间（有则记）。

## 推荐 persona 组合

- 必跑：`zero_patience_user`（2 次点击规则）+ `adversarial_skeptic`（S3 编造引用陷阱可并入本 scenario）。
- 轮换：`competition_judge`（180 秒计时版）、`enterprise_reviewer`（抽查 3 条 + 版本范围）。
