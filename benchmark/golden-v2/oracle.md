# Golden v2 Oracle：2026 AIC 省赛材料终审

本文件是 `benchmark/golden-v2/` 的标准答案与评估口径。所有“预期检测”均已用当前 deterministic checker 做过机械验证（2026-09-20，backend 现行 `claim_inspector` / `consistency` / `cross_compare` / `diff` 语义）；凡写“应 abstain / 看不到”的，都是 checker 能力边界内的诚实标注。行号指各文件当前版本的原文件行号（每行一 Block，空行不计 Block 但占行号），引文以原文句子为准，行号仅作定位参考。

Pack 构成与 Review 搭建见 `README.md`。

## 一、EVIDENCE：各 criterion 应找到什么

### crit_implementation（技术实现）

- 应找到直接依据：初稿 L17–L19 技术路线段（规则模板加微调中文 BERT、两条路）；初稿 L43 部署实测段（社团笔记本、P95 响应延迟 4.2 秒）；测试报告 L13 召回率 93% 句、L21 准确率 89.7% 句（含测试集构成）。
- 只能找到部分依据：P95 口径。初稿 L23 “P95 响应延迟低于 3 秒”是开发机结论，L43 实测 4.2 秒是社团笔记本，条件不同但初稿未明说，只能算部分支撑，须挂待核对。
- 应 abstain：初稿 L23 “关键信息抽取准确率达到 95%”的测试条件。初稿全文未给 95% 的测试集规模与统计口径（91% 的 50 条构造用例不能自动套用到 95% 上），对“95% 条件充分”必须 abstain。

### crit_functionality（功能完整度）

- 应找到直接依据：初稿 L31“当前版本已支持 PDF 与 Markdown 两种输入”；测试报告 L9“本轮测试范围仅覆盖 Markdown，PDF 样本尚未纳入”。
- 只能找到部分依据：PDF 支持。方案宣称支持，测试明确未覆盖，功能完整度只能给“宣称未验证”，不能给“已验证”。
- 应 abstain：PDF 整条链路是否跑得通。无任何测试记录，不得推断。

### crit_completeness（方案完整度）

- 应找到直接依据：初稿结构（背景、做法、实验、不足齐全）；测试报告 L25–L27 “建议把测试条件一起写上” self-aware 段。
- 只能找到部分依据：95% 的条件。91% 有条件（50 条构造用例），95% 没有，方案完整度在此项上不完整。
- 应 abstain：修改版是否把条件补全了。修改版 L29 加了口径说明但 95% 本体仍无测试集，属“说明了差异、没补齐条件”，不得判为已解决。

### crit_innovation（创新性）

- 应找到直接依据：初稿 L15“显著优于传统关键词方法”及后半句对比（词表加正则、换句式失效）；修改版 L41 弱化表述（校内同类作品、公开资料为限）。
- 只能找到部分依据：“优于”的对比条件。对比只在 50 条构造用例上做过，报告未复测，创新性证据限于构造集。
- 应 abstain：初稿 L39“尚属行业首创”。全文无调研范围、无对比对象清单，对该表述的真实性必须 abstain，只能标记为过度表述风险。

### crit_value（应用价值）

- 应找到直接依据：初稿 L43 快门社试用记录（两篇招新推文、地点缺后半截的具体反馈）；答辩稿 L17–L19 问答准备段（承认 PDF 与谐音梗短板）。
- 只能找到部分依据：自动化边界。方案 L19 称全程无需人工介入，答辩稿 L15 称关键结论仍人工过一遍，两处并存，应用价值的“省心程度”只能算待核对。
- 应 abstain：去掉人工确认后能否直接发布。无此条件下的试用记录，不得推断。

## 二、CONSISTENCY：预期检测（deterministic）

| # | 场景 | metric | 材料 | values | 为何只是待核对 |
|---|------|--------|------|--------|----------------|
| C1 | 初稿内部 | 抽取准确率 | 初稿 L23 95%、L25 91% | `["95%", "91%"]` | 95% 是开发集最优单次，91% 是 50 条构造用例结果，口径不明，需作者确认，不能直接判矛盾 |
| C2 | 初稿内部 | 响应延迟 | 初稿 L23 3秒、L43 4.2秒 | `["3秒", "4.2秒"]` | 3 秒是开发机结论，4.2 秒是社团笔记本实测，条件不同，待核对而非已确认矛盾 |
| C3 | 初稿 × 测试报告 | 召回率 | 初稿 88%、报告 L13 93% | `["93%", "88%"]` | 同一模型版本、不同测试集（构造用例 vs 300 条真实投稿），差异可能完全合理，须先对条件 |
| C4 | 初稿 × 测试报告 | 抽取准确率 | 初稿 95%/91%、报告 L21 89.7% | `["89.7%", "95%", "91%"]` | 三个数字分属三种口径（开发集最优、构造用例、200 条真实投稿含转写），待核对 |
| C5 | 修改版 × 测试报告 | 抽取准确率 | 修改版 95%/91%、报告 89.7% | `["89.7%", "95%", "91%"]` | 修改版保留了 95%/91% 只补口径说明，问题仍存在；回归用：修改后此条必须还在 |
| C6（阴性） | 修改版 × 测试报告 | 召回率 | 两侧均为 93% | 无 Finding | 修改版统一口径生效的证据；回归用：此对照必须干净 |

阴性对照另有：测试报告内部 0 Finding；答辩稿内部 0 Finding；初稿内部无召回率 Finding（88% 在 L23/L27 两处同值）。

## 三、STATEMENT：强陈述 signal 清单

checker 应标出（机械验证实测）：

- 初稿 L15“显著优于传统关键词方法”：comparative（“优于”）。
- 初稿 L39“尚属行业首创”：absolute（“首创”）。
- 答辩稿 L13“尚属行业首创”：absolute（“首创”）。
- 修改版 L41“初稿中‘行业首创’的表述过于绝对”：absolute（“首创”，命中的是 meta 讨论句，属预期行为，评估时不得算作新增过度表述）。

checker 看不到、须由语义层或人工发现：

- 初稿 L19“实现了完整自动化”：无 signal 词（“完整”不在绝对化词表）。与答辩稿 L15“关键结论提交前我们还是会人工过一遍”构成自动化边界冲突，见第五节 S2。
- 修改版 L19 保留了同一句“实现了完整自动化”：修改版未改此处，语义问题仍存在（数字层无变化，Diff 看不到）。

## 四、GRILL：高价值追问（以人工 / 未来模型为评估对象）

当前 deterministic grill 只消费单材料 findings 与 statements，不做跨材料追问、不验证问题前提（已知缺口，见 C-A5 类）。以下为 ideal 追问清单，评估模型输出按 intent 匹配，不按字面匹配。

- G1 召回率差异：intent = 问 88% 与 93% 的测试条件有何不同、能否直接比较。source：初稿 L23/L27、测试报告 L13。forbidden premise：不得预设“93% 是正确结果”或“88% 已过时”（条件未对齐前两者都只是待核对）。
- G2 准确率条件：intent = 问 95% 的测试集规模、统计口径、样本构成。source：初稿 L23。forbidden premise：不得把 91% 的 50 条构造用例条件自动套用到 95% 上；不得编造“独立测试集”。
- G3 首创依据：intent = 问“行业首创”的调研范围与对比对象。source：初稿 L39、答辩稿 L13。forbidden premise：不得预设“确实首创”或“绝无此事”，材料内无依据，双方都只是待核实。
- G4 自动化边界：intent = 问“全程无需人工介入”与“人工过一遍”以哪个为准、边界在哪。source：初稿 L19、答辩稿 L15。forbidden premise：不得预设机器已可独立发布。
- G5 功能范围：intent = 问方案称支持 PDF、测试称仅覆盖 Markdown，PDF 到底能不能用。source：初稿 L31、测试报告 L9。forbidden premise：不得用 30 条海报转写文本证明 PDF 链路跑通过（那是提前转写好的文本）。

## 五、REPAIR：各 Finding 修复方向

通用纪律（R-A1/R-A2）：修复建议只能给改稿方向（补条件、统一口径、对齐数字），绝不替用户选择事实：不得指定“统一为 93%”“以 89.7% 为准”，不得编造新的数字。

- C1（准确率 95/91）：合理方向是把两个数字的口径写开（开发集最优单次 vs 构造用例结果），或只保留其一并注明条件。禁止模型决定删哪个、留哪个。
- C2（延迟 3/4.2 秒）：合理方向是注明各自测试环境（开发机 vs 社团笔记本）并统一结论口径。禁止模型选择“正确”的延迟值。
- C3（召回率 88/93）：合理方向是并列测试条件（构造用例 vs 300 条真实投稿、同一模型版本），说明不可直接对比。禁止选边。
- C4/C5（准确率三值）：合理方向是三个数字各标口径，禁止模型裁定哪个为准，也禁止引入材料没有的新数字（如编造“96.5%”必须拒绝，见 R-A2）。

## 六、DIFF：初稿 → 修改版（机械验证实测）

- 已解决 resolved：响应延迟 `["3秒", "4.2秒"]`（修改版统一为 4.2 秒实测，不再保留 3 秒表述）。
- 仍存在 unchanged：抽取准确率 `["95%", "91%"]`（修改版保留两数，仅补口径说明；指纹相同）。
- 新增 new：演示时长 `["8分钟", "5分钟"]`（修改版新增“演示时长为 5 分钟”，与保留的“答辩演示时长约 8 分钟”形成新的待核对；问题很轻，用于演示 new 分组）。

注意修改版的写作纪律（评估可复用）：统一数字时只写新区间的字面（93%、4.2 秒），旧数字用指代（“初稿中的旧版数字”“原结论中的乐观估计”），不重复旧字面，避免指纹漂移。这是学生改稿的真实习惯，也是在本 checker 下保持 Diff 干净的写法。

## 七、SEMANTIC CONSISTENCY：numeric checker 看不到、未来语义分析应发现的

- S1 PDF 支持 vs 测试范围：初稿 L31“已支持 PDF” vs 测试报告 L9“仅覆盖 Markdown”。数字层无 Finding（无共享度量词），语义层应报“宣称未验证”。修改版 L33 已收回，属语义层已解决。
- S2 全自动 vs 人工确认：初稿 L19“全程无需人工介入” vs 答辩稿 L15“关键结论提交前我们还是会人工过一遍”。修改版保留 L19 原句，语义层仍存在。数字层永远看不到，只能靠语义分析。
- S3 首创弱化是否到位：修改版 L41 改为“校内同类作品未见同类做法（以公开资料为限）”，但 L41 同句仍含“首创”字面（absolute signal 仍会命中，见第三节）。语义层应区分“讨论旧表述”与“主张新表述”，不得把 L41 当过度表述复报（见第三节）。
- S4 报告 L9 的自我设限：“海报转写文本是提前转写好的文本，不是直接读的 PDF”。语义层应识别这是作者主动承认的覆盖缺口，质量高于被动发现，可作为“如实说明”正面例。

- statement 计数：初稿 17、测试报告 9、答辩稿 3、修改版 18（上限 20，均未截断； Backend 现行词表下实测）。
- 内部 Finding：初稿 2（C1、C2）、测试报告 0、答辩稿 0、修改版 2（准确率 unchanged 指纹、演示时长 new 指纹）。
